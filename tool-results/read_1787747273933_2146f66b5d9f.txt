     9→## 1. Project Overview
    10→
    11→**Phoenix v5.1** เป็น Bitcoin DCA (Dollar-Cost Averaging) trading bot ที่ทำงานอัตโนมัติบน GitHub Actions ซื้อขาย BTC รายวัน โดยใช้ on-chain metrics + technical indicators ในการตัดสินใจ
    12→
    13→### Core Idea
    14→- **DCA แบบ dynamic:** ไม่ซื้อที่เท่าเดิมทุกวัน แต่ปรับยอดซื้อตามสภาพตลาด (MVRV, SOPR, RSI, MACD)
    15→- **ขายแบบ tiered:** ใช้ sell scoring system + triple-trigger gate ขายเป็นสัดส่วนตามระดับ euphoria
    16→- **Reserve deployment:** เก็บกำไรจากการขาย BTC ไว้ deploy ซื้อเพิ่มตอนตลาดถดถอย
    17→
    18→### Architecture Summary
    19→
    20→```
    21→GitHub Actions (cron 20:00 THB)
    22→  → main.py (CLI)
    23→    → engine.run_daily()
    24→      ├── config.py          — ตั้งค่าทั้งหมด
    25→      ├── bitkub_client.py   — API ซื้อขาย/ดึงราคา
    26→      ├── indicators.py      — SMA, RSI, MACD (pure numpy)
    27→      ├── strategy.py        — Phoenix v5.1 decision logic
    28→      ├── bg_metrics.py      — BGeometrics on-chain cache
    29→      ├── mvrv_fetcher.py    — MVRV web fallback
    30→      ├── state.py           — state persistence (JSON + fcntl lock)
    31→      ├── kill_switch.py     — L1 (env) + L2 (JSON) safety
    32→      └── notifier.py        — Telegram alerts
    33→    → generate_dashboard.py
    34→    → git push → GitHub Pages
    35→```
    36→
    37→### Concurrency Protection
    38→- **`.bot_lock` file** (in `live_bot/`): `main.py` creates `fcntl.flock(LOCK_EX)` on startup
    39→  - Lock age > 30 min = stale, auto-removed (previous crash)
    40→  - Prevents overlapping GitHub Actions runs from trading simultaneously
    41→- **State file locking** (`state.py`): `load_state()` uses `LOCK_SH` (shared/read), `save_state()` uses `LOCK_EX` (exclusive/write)
    42→  - Lock file: `state.json.lock`
    43→  - Atomic writes via `tempfile.mkstemp()` + `os.replace()` — readers always see valid JSON
    44→- **Trade log locking**: Same pattern — `LOCK_SH` for read, `LOCK_EX` for append (read-modify-write atomic)
    45→  - Lock file: `trade_log.json.lock`
    46→  - Corrupted JSON recovery: `JSONDecodeError` → backup corrupted file → return empty list
    47→- **GitHub Actions concurrency**: `dca-any-exchange` group, `cancel-in-progress: false`
    48→  - 3 cron slots (20:00/20:10/20:30 THB) wait for each other, do not cancel
    49→
    50→### Design Principles
    51→- **Zero pandas** — pure numpy + stdlib only (lightweight for GitHub Actions)
    52→- **No TA-Lib** — all indicators hand-rolled in `indicators.py`
    53→- **File-based state** — JSON committed to repo (no database)
    54→- **Thai timezone** — all date logic uses UTC+7 (`_thai_today()`)
    55→- **Idempotent** — same day re-runs are no-ops (unless `--force`)

   128→## 3. Data Flow — One Complete Run
   129→
   130→### `run_daily()` 13-Step Pipeline
   131→
   132→```
   133→Step 0:  Idempotency check — skip if last_run_date == today (THB timezone)
   134→         Also checks trade_log for daily buy count (dual-layer protection)
   135→Step 0c: D3 transition (dry-run to live auto-reset):
   136→         If last_dry_run == True and this is a live run:
   137→         - Reset ALL counters: total_invested, total_btc_bought, total_sell_proceeds,
   138→           cumulative_fees, peak_value, max_drawdown, sell_proceeds_reserve,
   139→           total_reserve_injected, buy_count, sell_count
   140→         - Clear trade_log.json atomically (clear_trade_log with LOCK_EX)
   141→         - Reset last_trade_date, last_sell_date, realized_price, lth_realized_price
   142→Step -1: Kill switch — L1 (env BOT_ENABLED) + L2 (kill_switch.json)
   143→Step 1:  Fetch BTC price from exchange
   144→Step 2:  Fetch 500-day price history (Binance Vision ZIP → CoinGecko fallback)
   145→Step 3:  Compute indicators: SMA200, SMA365, RSI(14), MACD, MACD series, RSI divergence, ATH
   146→Step 4:  Get MVRV value (priority chain):
   147→          1. BG cache (disk-only via `get_cached_value()`, 0 API calls)
   148→          2. Embedded `_mvrv_history.py` — 4000+ days, exact lookup → 7-day nearest fallback
   149→          3. CoinMetrics Community API (free, no key, metric `CapMVRVCur`)
   150→          4. ahasignals.com scrape (regex on HTML, last resort)
   151→          If ALL fail → skip trade + Telegram warning
   152→          Source tracked as: 'BG-cache', 'BG', 'embedded', 'CoinMetrics', 'ahasignals'
   153→
   154→Step 4b: BGeometrics batch fetch (only if cache stale >3 days):
   155→          `get_all_metrics_today()` — the ONLY place BG API is called
   156→          Fetches 5 metrics: sth_sopr, lth_realized_price, realized_price, mvrv, mvrv_zscore
   157→          Fallbacks if BG unavailable:
   158→            - STH-SOPR: SMA14 proxy (price/sma14)
   159→            - LTH-RP: realized_price × 1.15 proxy
   160→            - MVRV Z-Score: embedded 365d rolling Z-Score (computed from _mvrv_history.py)
   161→          Source tracked as: 'BG', 'cache-stale', 'proxy-sma14', 'embedded-365d'
   162→Step 5:  Get balances (live: exchange API / dry-run: virtual from state)
   163→Step 6:  Convert budget THB → exchange currency
   164→Step 6b: Calculate usable reserve (sell_proceeds - invested_from_reserve)
   165→Step 7:  Decrement cooldown (if > 0)
   166→Step 8:  Run phoenix_v5_1_decision() → {buy_amount, sell_amount, sell_score, path}
   167→Step 9:  Execute trades:
   168→          Buy: check min order (10 THB), check cash
   169→          Sell: never sell >99% of BTC
   170→Step 10: Update state (portfolio value, peak, max drawdown, adjusted_invested)
   171→Step 11: Snapshot all indicators to state (for dashboard)
   172→Step 12: Low balance warning if cash/budget <= 7 days
   173→Step 13: Telegram notification with daily report
   174→```
   175→
   176→### Critical Order Dependencies
   177→- **Step 0c (D3)** must run before Step -1 (kill switch) — D3 kill switch check re-runs are safe
   178→- **Step 4 (MVRV)** must run before **Step 4b (BG batch)** — MVRV from cache for NUPL
   179→- **Step 4b** is the ONLY place that calls BG API — daily guard prevents duplicates
   180→- **Step 4b MVRV override** only triggers if bg_mvrv_val > 0 (B7 fix)
   181→- **Step 9** writes trade_log BEFORE state (H2 fix)
   182→- **Step 10** updates `adjusted_invested` on sell: `adjusted_invested *= (1 - sell_fraction)`

   186→## 4. Strategy Logic — Phoenix v5.1
   187→
   188→### Buy Decision (Dynamic DCA)
   189→
   190→Buy amount = `min(base_budget × multiplier, max_buy)`
   191→
   192→#### MVRV-Based Tiers
   193→
   194→| MVRV Range | Extra Condition | Multiplier | Zone |
   195→|------------|----------------|------------|------|
   196→| < 1.0 | SOPR < 0.95 | **4.5×** | Heavy accumulation (underwater) |
   197→| < 1.0 | SOPR ≥ 0.95 | **3.0×** | Strong accumulation |
   198→| 1.0 – 1.5 | NUPL < 0.25 | **3.0×** | Early bull |
   199→| 1.0 – 1.5 | NUPL ≥ 0.25 | **2.0×** | Moderate bull |
   200→| 1.5 – 2.0 | — | **1.0×** | Normal DCA |
   201→| 2.0 – 2.5 | — | **0.3×** | Reduced |
   202→| ≥ 2.5 | — | **0.0×** | No buying |
   203→
   204→#### Reserve Deployment (from BTC sale profits only)
   205→
   206→| Condition | Deploy Rate |
   207→|-----------|-------------|
   208→| MVRV < 0.8 + bear | 25% of usable reserve |
   209→| MVRV < 0.9 + bear | 20% |
   210→| MVRV < 1.0 | 15% |
   211→| MVRV < 1.1 | 10% |
   212→| MVRV < 1.3 | 6% |
   213→| MVRV 1.3 – 1.5 | 3% |
   214→
   215→**Boost:** If `price < realized_price × 1.05` → injection × 1.8 (capped at `max_reserve_boosted`)
   216→
   217→### Sell Decision (Scoring + Triple-Trigger Gate)
   218→
   219→#### Scoring Table
   220→
   221→| Signal | Points | Notes |
   222→|--------|--------|-------|
   223→| MVRV > 2.5 | +20 | |
   224→| MVRV > 3.0 | +15 | |
   225→| MVRV > 3.5 | +10 | |
   226→| MVRV > 4.0 | +10 | |
   227→| RSI > 65 | +5 | Partial credit |
   228→| RSI > 70 | +5 | |
   229→| RSI > 80 | +7 | |
   230→| MVRV pct ≥ 92% | +12 | 365-day percentile |
   231→| MVRV pct ≥ 97% | +8 | |
   232→| MVRV Z > 3.0 | +8 | BG Z-Score or embedded 365d |
   233→| MVRV Z > 4.0 | +7 | |
   234→| MACD bear cross | +10 | Histogram crossed below 0 |
   235→| MACD declining 4 bars | +5 | Consecutive decline |
   236→| RSI divergence | +15 | Price high + RSI lagging |
   237→| Price/LTH-RP > 3.0 | +8 | |
   238→| Price/LTH-RP > 3.5 | +5 | |
   239→| Price/LTH-RP > 4.0 | +5 | |
   240→| ATH proximity >97% | +7 | |
   241→| NUPL > 0.70 | +5 | |
   242→| NUPL > 0.80 | +5 | |
   243→| **In bear market** | **−200** | **Blocks ALL sells** |
   244→
   245→#### Triple-Trigger Gate (paths)
   246→
   247→```
   248→Path A:       MVRV > 2.5 AND score ≥ 45
   249→Path A-Ext:   MVRV 2.0–2.5 AND pct ≥ 95% AND Z ≥ 2.5 AND score ≥ 48
   250→Path B:       MVRV > 2.0 AND pct ≥ 92% AND score ≥ 48
   251→
   252→If NO path active → sell_score forced to 0 (no sell)
   253→```
   254→
   255→#### Sell Execution Tiers
   256→
   257→| Path | Score Range | Sell % | Cooldown |
   258→|------|------------|--------|----------|
   259→| A | ≥ 75 | 40% | 35 days |
   260→| A | 60–74 | 18% | 28 days |
   261→| A | 50–59 | 8% | 22 days |
   262→| A | 45–49 | 4% | 18 days |
   263→| A-Ext | ≥ 48 | 8% | 22 days |
   264→| B | ≥ 56 | 8% | 28 days |
   265→| B | 48–55 | 4% | 22 days |
   266→
   267→### Bear Market Detection
   268→
   269→```python
   270→in_bear = price < sma_200  # Simple: price below 200-day SMA
   271→```
   272→
   273→**Effects of `in_bear = True`:**
   274→- Sell scoring: −200 points (blocks ALL sells regardless of other signals)
   275→- Reserve deployment: higher rates for MVRV < 0.8/0.9 tiers (25%/20% vs 15%/10%)
   276→- This is a simple but effective guard against selling in a downtrend
   277→
   278→### Return Dict
   279→
   280→```python
   281→{
   282→    'buy_amount': float,        # THB/USDT to buy (0 = no buy)
   283→    'sell_amount': float,       # BTC to sell (0 = no sell)
   284→    'sell_score': int,          # 0-200+
   285→    'new_cooldown': int,        # days to wait after sell
   286→    'sell_path': str,           # 'A', 'A-Ext', 'B', or 'none'
   287→    'reserve_injection': float, # from sale profits
   288→    'in_bear': bool,            # bear market flag
   289→}
   290→```

   294→## 5. Exchange Clients
   295→
   296→### Bitkub (`bitkub_client.py`) — Primary, THB
   297→
   298→**Auth Formula (CRITICAL — ถ้าผิดจะได้ 400 Bad Request):**
   299→
   300→```python
   301→# Signature = HMAC-SHA256(timestamp + METHOD + path + body, api_secret)
   302→# NOTE: NO api_key in payload! MUST include HTTP method!
   303→
   304→ts = str(int(time.time() * 1000))  # milliseconds
   305→msg = ts + 'POST' + '/api/v3/market/wallet' + '{}'
   306→sig = hmac.new(api_secret.encode(), msg.encode(), hashlib.sha256).hexdigest()
   307→
   308→# Headers:
   309→# X-BTK-APIKEY: api_key
   310→# X-BTK-TIMESTAMP: ts
   311→# X-BTK-SIGN: sig          ← NOT 'X-BTK-SIGNATURE'
   312→# Accept: application/json
   313→# Content-Type: application/json
   314→```
   315→
   316→**Endpoints:**
   317→
   318→| Method | Path | Purpose | Auth? |
   319→|--------|------|---------|-------|
   320→| GET | `/api/v3/market/ticker?sym=BTC_THB` | Price | No |
   321→| POST | `/api/v3/market/wallet` | Balance | Yes |
   322→| POST | `/api/v3/market/place-bid` | Buy (amt=THB) | Yes |
   323→| POST | `/api/v3/market/place-ask` | Sell (amt=BTC) | Yes |
   324→
   325→**Response Gotchas:**
   326→- HTTP 200 with `error: 0` = **SUCCESS** (not failure!)
   327→- HTTP 200 with `error: 42` = application error (e.g., insufficient balance)
   328→- Wallet response: `result.BTC = 8.9` (flat number, NOT `result.BTC.available`)
   329→- Buy response: `result.recv` = BTC received, `result.cost` = THB spent
   330→- Sell response: `result.recv` = THB received (after fee)
   331→- Min order: **10 THB** (not 100)
   332→
   333→**Price History (OHLCV):**
   334→1. Binance Vision (`data.binance.vision`) — ZIP/CSV, converts USDT→THB
   335→2. CoinGecko — fallback, ~90 days on free tier
   336→
   337→### Binance (`binance_client.py`) — Alternative, USDT
   338→
   339→**Auth Formula:**
   340→```python
   341→# Signature = HMAC-SHA256(sorted_query_string, api_secret)
   342→# query_string = timestamp=X&recvWindow=5000&symbol=BTCUSDT&...
   343→# Header: X-MBX-APIKEY: api_key
   344→```
   345→
   346→**Geo-Block Fallback (HTTP 451):**
   347→- Price: Kraken → KuCoin → CoinCap → CoinGecko
   348→- Klines: Kraken (720/batch) → KuCoin (300/batch) → CoinCap → CoinGecko
   349→
   350→**Key Differences from Bitkub:**
   351→- Buy uses `quoteOrderQty` (USDT amount), not `amt`
   352→- Sell uses `quantity` (BTC, 6 decimals)
   353→- No `fee` in response — engine uses `cost × fee_pct`
   354→- Pagination: max 1000 candles per request

   358→## 6. BGeometrics Cache (`bg_metrics.py`)
   359→
   360→### Design Goals
   361→- **Minimize API calls** — BG free tier: 10 req/hr
   362→- **Historical data is IMMUTABLE** — never re-fetched
   363→- **Incremental only** — fetches only if cache newest > 3 days behind today
   364→
   365→### Rate Limit Protection Layers
   366→
   367→| Layer | Mechanism | Saves |
   368→|-------|-----------|-------|
   369→| 1 | `get_cached_value()` — disk only, 0 API calls | Used for early MVRV check in engine step 4 |
   370→| 2 | Daily guard — in-memory snapshot, 0 API calls after 1st fetch/day | Same-process re-runs |
   371→| 3 | Freshness check — skip fetch if cache < 3 days stale | Normal daily runs |
   372→| 4 | Hourly counter — max 10 req/hr, hard stop | Emergency brake |
   373→
   374→### Typical API Usage
   375→
   376→| Scenario | API Calls |
   377→|----------|-----------|
   378→| Cache fresh (< 3d stale) | **0** |
   379→| Cache stale + first run of day | **0–5** (one per metric) |
   380→| 2nd+ run same day | **0** (daily guard) |
   381→
   382→### Functions
   383→
   384→```python
   385→# CACHE ONLY — never calls API (use for early reads)
   386→get_cached_value('mvrv', today)           # → float or NaN
   387→
   388→# BATCH FETCH — calls API only if cache stale > 3 days
   389→# Returns dict with: sth_sopr, lth_realized_price, realized_price, mvrv, mvrv_zscore
   390→# Also sets: sopr_source, mvrv_source, mvrv_z_source
   391→get_all_metrics_today(target_date=today)   # → dict
   392→
   393→# FULL CACHE for backtest
   394→ensure_cache()                             # → cache dict
   395→get_cached_series('sth_sopr')               # → {date_str: float}
   396→```
   397→
   398→### Cache File (`bg_cache.json`)
   399→
   400→```json
   401→{
   402→  "metrics": {
   403→    "sth_sopr": {"2022-08-05": 1.02, ...},
   404→    "mvrv_zscore": {"2022-08-20": -0.5, ...}
   405→  },
   406→  "last_fetch": {
   407→    "sth_sopr": "2026-08-18T09:50:50+00:00"
   408→  }
   409→}
   410→```
   411→
   412→- Up to 5 years (1826 days) per metric
   413→- Trimmed from oldest after merge
   414→- Atomic writes via `tempfile + os.replace()`
   415→- Smart key detection: if expected JSON key yields 0 results, auto-detects by scanning
   416→
   417→### `_SINGLE_VALUE_METRICS`
   418→
   419→Metrics where `min_days=1` is sufficient (API returns few values, not full history):
   420→- Currently: `{'sth_realized_price'}` only
   421→- `lth_realized_price` and `realized_price` were REMOVED from this set because BG now returns full history

   543→## 10. Common Pitfalls & Gotchas
   544→
   545→### Bitkub API
   546→1. Signature: HMAC-SHA256(ts + METHOD + path + body, secret) - NO api_key in payload
   547→2. Header: X-BTK-SIGN (not X-BTK-SIGNATURE)
   548→3. error: 0 = success (do not throw)
   549→4. Wallet: /api/v3/market/wallet POST (not /balances)
   550→5. Wallet format: flat {"BTC": 8.9} not nested
   551→6. Buy: THB for place-bid, BTC for place-ask
   552→
   553→### BGeometrics
   554→7. Use get_cached_value() for early reads (0 API calls)
   555→8. Rate limit: 10 req/hr free tier
   556→9. Data lag: BG always 1-2 days behind (normal)
   557→10. Freshness = 3 days: cache within 3 days skips fetch
   558→
   559→### Engine / State
   560→11. Thai timezone (UTC+7) for all dates
   561→12. Never sell >99% of BTC
   562→13. Kill switch skips idempotency (last_run_date NOT updated)
   563→14. adjusted_invested *= (1 - sell_fraction) on sell
   564→15. _sanitize_for_json() converts NaN/Inf to null
   565→16. Trade log BEFORE state (H2 fix)
   566→17. actual_buy_cost: use exchange return, not decision amount
   567→18. Timeout buy: assume executed, estimate from sent amount
   568→19. D3 transition: auto-resets ALL counters + clears trade_log
   569→20. BG MVRV override: guard > 0 only (B7)
   570→21. _no_trade() preserves cooldown (B6)
   571→
   572→### GitHub Actions
   573→22. Boolean unchecked = "" NOT "false" - use = "true"
   574→23. Git push: auto-stash + rebase
   575→24. bg_cache.json must be in git add
   576→25. Separate state/dashboard commits (C7)
   577→26. if: always() on dashboard step
   578→27. Telegram alert needs env: block (B15)
   579→28. Python one-liners need imports (B14)
   580→
   581→### Dashboard
   582→29. fmt_num() in JS needs quotes (B11)
   583→30. Unix timestamps for freshness, not datetime (B9)
   584→31. html.escape() on all user-derived strings (H4)
   585→
   586→### Indicators
   587→32. RSI: Wilder smoothing (alpha=1/period)
   588→33. MACD bear cross: latest bar only
   589→34. RSI divergence: price>=97% 40d high + RSI>=8pts below + RSI>=58
   590→35. MVRV<=0 = treat as NaN (H6)
