   530→### (a) Exact Root Cause
   531→
   532→**The problem has TWO layers:**
   533→
   534→**Layer 1 — Remote tracking refs are non-existent.**
   535→The btc-signal-analyzer repo was created via `git init` locally (reflog shows `commit (initial)`) and was NEVER cloned from GitHub. Consequently:
   536→- `git fetch origin` has never been successfully run

   539→- No upstream tracking is configured (`git branch -vv` shows bare `main` with no `[origin/main]`)
   540→- `git fetch origin` CANNOT work because the remote URL (`https://github.com/...`) has no authentication and no credential helper is configured
   541→
   542→**Layer 2 — `git push <auth_url> main` (line 120) does NOT update remote tracking refs.**
   543→When `git push` is given a raw URL instead of a remote name, git pushes the objects and updates the REMOTE refs, but it does NOT create or update any local remote tracking refs (`refs/remotes/origin/*`). This is by design in git. The script's approach of pushing via authenticated URL bypasses the remote configuration entirely, so `origin/main` is never born.
   544→
   545→**Why the file is 404 on raw.githubusercontent.com:**
   546→The push syntax `git push <url> main` IS valid (confirmed via local bare-repo testing — it correctly pushes `refs/heads/main` to the remote). If the push is reaching GitHub with a valid token, the most likely reason for 404 is that **the btc-signal-analyzer repo is PRIVATE** — raw.githubusercontent.com returns 404 (not 403) for private repos to avoid information leakage. If the repo is public and the push is failing, the error would be in `push_result.stderr` (exit code non-zero) and the script would return False.
